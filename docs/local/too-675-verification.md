使用既有分组 6、7，分别选中账号 5、6；两个账号使用不同的原生 OpenAI API Key。共 12 次真实调用：4 次直连、8 次经网关，全部 HTTP 200。输入均为合成验收文本，每次包含 predicate、choice、score 三种问题，以及布尔值 `true` 与字符串 `"true"` 两个不同选项。

| 分组 / 实际账号 | 直连 / 网关次数 | 首轮输入 / 缓存写入 | 网关独立前缀输入 / 缓存写入 | 后续缓存读取 |

| 7 / 6 | 2 / 4 | 2767 / 2404 | 2782 / 2419 | 对应读取 2404、2419 |

每次普通输入均为 363 token，输出为 0。首轮直连预热缓存，随后网关读取；第二轮换独立输入前缀，先经网关产生真实缓存写入，再验证读取，并以直连对照。问题名称、答案顺序、三种类型及 choice 的值与类型均一致；predicate 判定一致，score 差异处于约定的 0.05 内。概率不要求两次调用逐位相同。

按已核对的端点价格估算，12 次真实上游调用合计 USD 0.001834270；这是基于真实 token 的估算，不是供应商账单回执。

### 鉴权、错误与取消

| 场景 | 结果 |
| --- | --- |
| 缺少、无效或停用的下游 Key | 401，未记账 |
| Key 配额耗尽 / 用户余额不足 | 429 / 403，未记账 |
| 无权使用专属分组 / 分组停用 | 403，分别保留 `GROUP_NOT_ALLOWED` / `GROUP_DISABLED` |
| 分组模型白名单拒绝 | 404，未记账 |
| 模拟上游 400 / 429 / 500 | 保留状态与错误语义；429 保留 `Retry-After`；每次仅一次上游尝试 |
| 模拟上游回显自己的凭据 | 下游正文脱敏，400 和业务错误码保留 |
| 成功响应损坏 / 缺少真实用量 | 502，不重放、不记成功账单 |
| 未知模型缺少价格 | 503，上游调用次数为 0 |
| 顶层重复 `model` | 400，上游未收到请求，未新增账单 |
| 请求尚未转发时客户端取消 | 访问日志 499，未记账 |
| 上游已收到请求后客户端取消 | 访问日志 499，上游观察到连接取消，用户和账号并发槽均释放，未记账 |
| 实际上游响应头超时 | 测试进程配置 3 秒响应头超时，HTTP 504，上游观察到取消，槽位释放，未记账 |

错误与超时通过本机隔离模拟上游注入，鉴权、调度、网络转发、PostgreSQL 和 Redis 使用真实测试链路；没有故意向真实供应商发送错误或超时请求。两次实际取消/超时验证均确认模拟上游已进入处理，而非只在下游提前取消。
